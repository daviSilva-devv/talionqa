# Talion UI Skill

Use for product UI, layout, visual states and interaction design.

## Goal
Create a recognizable TalionQA experience, not a generic SaaS dashboard.

## Read first
- `docs/UI.md`
- relevant component/code only

## Rules
- White/off-white canvas + Talion purple identity.
- Prefer spatial/contextual interfaces over card grids.
- X-Ray is the primary product surface.
- Findings should appear in project context before long text.
- Use generous whitespace and clear hierarchy.
- Motion must communicate discovery, scan, impact, change or resolution.
- Keep critical colors localized; do not flood the interface red.
- Responsive/mobile behavior is required, not a later patch.
- Accessibility and keyboard/focus states are part of quality.

## Avoid
Generic dashboard templates, giant sidebars, arbitrary gradients, excessive pills, decorative glass, fake KPIs, visual noise.

## Output
When implementing UI, include a concise screenshot/visual verification note in the task/PR.
